Q2What is the difference between a list and a NumPy array?
▼
Python list
Flexible, slow
Can hold mixed types. Dynamic size. Slow for maths — loops element by element.
NumPy array
Typed, fast
Fixed type (homogeneous). Fixed size. Vectorised operations — 10–100x faster. Supports broadcasting.
# List — slow, iterates element by element lst = [1, 2, 3, 4] result = [x * 2 for x in lst] # need a loop # NumPy array — fast, vectorised arr = np.array([1, 2, 3, 4]) result = arr * 2 # no loop needed — broadcasts # Speed difference example import numpy as np arr = np.arange(1_000_000) # 100x faster than list equivalent
Say this
"Python lists can hold any mix of types and are flexible, but they're slow for numerical computation because operations iterate element by element. NumPy arrays are typed — all elements are the same dtype — and stored in contiguous memory, which allows vectorised operations that are 10 to 100 times faster. Broadcasting lets you apply operations across arrays of different shapes without loops. In data science you almost always use NumPy arrays over lists for any numerical work."
Q3What is broadcasting in NumPy?
▼

Broadcasting lets NumPy perform operations on arrays of different shapes without copying data.

# Without broadcasting — would need to repeat arr = np.array([[1,2,3],[4,5,6]]) # shape (2,3) scalar = 10 result = arr + scalar # adds 10 to every element — shape (2,3) # Row-wise operation row = np.array([1, 2, 3]) # shape (3,) result = arr + row # adds [1,2,3] to EACH row — broadcasts # [[2,4,6], [5,7,9]]
Say this
"Broadcasting is NumPy's way of performing operations on arrays with different shapes by implicitly expanding the smaller array to match the larger one — without actually copying memory. For example, adding a shape (3,) array to a shape (2,3) array broadcasts the row across both rows. It makes code clean and fast — no explicit loops or manual repetition needed."

Q5How do you handle missing values in Pandas?
▼
# Detect missing values df.isnull().sum() # count NaN per column df.isnull().sum() / len(df) # % missing per column df.isnull().any(axis=1) # rows with any missing value
# Drop missing df.dropna() # drop rows with ANY NaN df.dropna(subset=['salary']) # drop rows where salary is NaN df.dropna(thresh=5) # keep rows with at least 5 non-NaN
# Fill missing df['age'].fillna(df['age'].mean()) # fill with mean df['city'].fillna(df['city'].mode()[0]) # fill with mode (categorical) df['salary'].fillna(method='ffill') # forward fill (time series) df.fillna(0) # fill all NaN with 0
# Best practice: sklearn imputer (fits on train, transforms test) from sklearn.impute import SimpleImputer imp = SimpleImputer(strategy='mean') X_train = imp.fit_transform(X_train) X_test = imp.transform(X_test) # NOT fit_transform — avoids leakage
Say this
"First I check the extent of missing data with isnull().sum() — the strategy depends on how much is missing and why. Small amount with no pattern — impute with mean for numerical, mode for categorical. Large amount (over 40–50%) — consider dropping the column. Time series — forward fill. In production I always use sklearn's SimpleImputer which I fit on training data only and then transform both train and test separately — to avoid data leakage."
Q6What is groupby? Explain with examples.
▼
# Basic groupby — split → apply → combine df.groupby('department')['salary'].mean() df.groupby('department')['salary'].agg(['mean','median','count','std']) # Multiple groupby keys df.groupby(['department','gender'])['salary'].mean() # Custom aggregation with agg df.groupby('department').agg( avg_salary=('salary','mean'), total_employees=('id','count'), max_salary=('salary','max') ) # Apply a custom function df.groupby('dept')['salary'].apply(lambda x: x.max() - x.min())
Say this
"Groupby follows a split-apply-combine pattern — split the DataFrame into groups by a key, apply an aggregation or function to each group, then combine the results. It's one of the most-used Pandas operations. The agg method lets you apply multiple named aggregations at once — much cleaner than chaining. For custom logic I pass a lambda to apply. GroupBy + transform is useful when you want to add group-level stats back to the original DataFrame without collapsing rows."
Q7What is the difference between apply, map, and applymap?
▼
map()Series only. Element-wise operation or substitution using a dict or function. Fast. e.g. df['gender'].map({'M':0,'F':1})
apply()Series or DataFrame. Applies a function along axis (rows or columns). Flexible — handles complex custom logic.
applymap()DataFrame only. Element-wise on every single cell. Renamed to map() in Pandas 2.1+.
# map — element-wise on a Series df['gender'] = df['gender'].map({'M': 0, 'F': 1}) # apply — row/column-wise on DataFrame df['full_name'] = df.apply(lambda row: row['first']+' '+row['last'], axis=1) # apply on a Series for custom transform df['salary'] = df['salary'].apply(lambda x: x * 1.1 if x < 50000 else x)
Say this
"map works on a single Series element by element — great for encoding categories. apply works on a Series or DataFrame and can go row-wise or column-wise — use it for custom logic that can't be done with vectorised operations. applymap works on every individual cell of a DataFrame. In practice I prefer vectorised operations over apply wherever possible since apply loops under the hood and is slow on large DataFrames."
Q8How do you merge and join DataFrames in Pandas?
▼
# merge — like SQL JOIN pd.merge(df1, df2, on='id', how='inner') # inner join pd.merge(df1, df2, on='id', how='left') # left join pd.merge(df1, df2, left_on='id', right_on='customer_id', how='left') # join — joins on index df1.join(df2, how='left') # concat — stack DataFrames pd.concat([df1, df2], axis=0) # stack rows (same columns) pd.concat([df1, df2], axis=1) # stack columns (same rows)
Say this
"Pandas merge is the equivalent of SQL JOIN — it combines DataFrames on a shared key column. I use merge most of the time since it's explicit about which columns to join on and supports all join types. join is similar but joins on the index. concat is for stacking — axis=0 stacks rows vertically like UNION ALL, axis=1 stacks columns side by side. After any merge I always check the shape to confirm I got the expected number of rows — unexpected row counts signal duplicate keys or wrong join type."
Row explosion trap
If the join key has duplicates in both tables, merge creates a cartesian product of those rows. Always check df.shape before and after merge to catch unexpected row explosions.
Data cleaning
Q9How do you detect and remove duplicates?
▼
# Detect df.duplicated().sum() # count duplicate rows df.duplicated(subset=['email']).sum() # duplicates on specific col df[df.duplicated(subset=['email'], keep=False)] # show ALL duplicate rows # Remove df.drop_duplicates(inplace=True) # remove all full duplicates df.drop_duplicates(subset=['email'], keep='first') # keep first occurrence df.drop_duplicates(subset=['email'], keep='last') # keep most recent
Say this
"I check for duplicates early in EDA using duplicated().sum(). The key decision is what defines a duplicate — full row duplicates vs duplicates on a subset of columns like email or user_id. keep='first' retains the first occurrence and drops the rest. In event-log data I often want keep='last' to keep the most recent record per user. After dropping I always verify the shape reduced as expected."
Q10How do you detect and handle outliers in Python?
▼
# IQR method Q1 = df['salary'].quantile(0.25) Q3 = df['salary'].quantile(0.75) IQR = Q3 - Q1 lower = Q1 - 1.5 * IQR upper = Q3 + 1.5 * IQR outliers = df[(df['salary'] < lower) | (df['salary'] > upper)] df_clean = df[(df['salary'] >= lower) & (df['salary'] <= upper)] # Z-score method from scipy import stats z_scores = np.abs(stats.zscore(df['salary'])) df_clean = df[z_scores < 3] # Winsorize (cap instead of remove) df['salary'] = df['salary'].clip(lower=lower, upper=upper)
Say this
"I detect outliers using the IQR method — values outside Q1 minus 1.5 times IQR or Q3 plus 1.5 times IQR. For normally distributed data I use Z-scores with threshold 3. But before removing I always investigate — is it a data entry error or a genuine extreme value? If it's genuine I use clip to cap it at the fence value rather than deleting the row, preserving the observation while reducing its distortion."
Q11How do you encode categorical variables?
▼
# Label encoding — ordinal categories from sklearn.preprocessing import LabelEncoder le = LabelEncoder() df['grade'] = le.fit_transform(df['grade']) # A→0, B→1, C→2 # Ordinal encoding (preserves meaningful order) from sklearn.preprocessing import OrdinalEncoder oe = OrdinalEncoder(categories=[['Low','Medium','High']]) df[['level']] = oe.fit_transform(df[['level']]) # One-hot encoding — nominal categories pd.get_dummies(df, columns=['city'], drop_first=True) # OR sklearn from sklearn.preprocessing import OneHotEncoder ohe = OneHotEncoder(sparse=False, drop='first') # Target encoding — high cardinality columns # Replace category with mean of target for that category df['city_encoded'] = df.groupby('city')['salary'].transform('mean')
Say this
"Encoding choice depends on the type of categorical variable. For ordinal data with a meaningful order — like Low, Medium, High — I use OrdinalEncoder to preserve that order. For nominal data with no order I use one-hot encoding — drop_first=True removes one column to avoid multicollinearity. For high-cardinality columns like city with hundreds of values, one-hot creates too many columns so I use target encoding — replacing each category with the mean of the target for that category."
Target encoding leakage
Always compute target encoding means on training data only. If you compute on the full dataset the test set's target values leak into the encoding. Use sklearn's TargetEncoder in cross-validation to handle this safely.
Q12How do you scale features — normalisation vs standardisation in Python?
▼
# StandardScaler — zero mean, unit variance (standardisation) from sklearn.preprocessing import StandardScaler scaler = StandardScaler() X_train_scaled = scaler.fit_transform(X_train) # fit + transform X_test_scaled = scaler.transform(X_test) # transform only — no fit! # MinMaxScaler — scales to [0,1] (normalisation) from sklearn.preprocessing import MinMaxScaler scaler = MinMaxScaler() X_train_scaled = scaler.fit_transform(X_train) X_test_scaled = scaler.transform(X_test) # RobustScaler — uses median and IQR, robust to outliers from sklearn.preprocessing import RobustScaler scaler = RobustScaler()
Say this
"StandardScaler is my default — it standardises features to mean zero and standard deviation one. MinMaxScaler normalises to 0–1 but is sensitive to outliers. RobustScaler uses median and IQR instead of mean and std — so it's much less affected by extreme values. The most critical rule: always fit the scaler on training data only, then call transform on both train and test. Calling fit_transform on test data is a data leakage mistake."

Q15What is a sklearn Pipeline and why should you use it?
▼

Say this
"A sklearn Pipeline chains preprocessing steps and a model into a single object. The huge advantage is it prevents data leakage during cross-validation — without a pipeline, if you scale the full dataset before cross-validation, test fold statistics leak into training. With a pipeline, sklearn refits the scaler on each training fold and transforms the validation fold separately. It also makes deployment clean — you deploy one pipeline object that handles everything from raw data to prediction."

Q17How do you tune hyperparameters — GridSearchCV vs RandomizedSearchCV?
▼
from sklearn.model_selection import GridSearchCV, RandomizedSearchCV from sklearn.ensemble import RandomForestClassifier # GridSearchCV — tries every combination param_grid = { 'n_estimators': [100, 200, 300], 'max_depth': [5, 10, None], 'min_samples_split': [2, 5] } grid = GridSearchCV(RandomForestClassifier(), param_grid, cv=5, scoring='f1', n_jobs=-1) grid.fit(X_train, y_train) print(grid.best_params_) print(grid.best_score_) # RandomizedSearchCV — samples n random combinations from scipy.stats import randint param_dist = { 'n_estimators': randint(100, 500), 'max_depth': [5, 10, 20, None] } rand = RandomizedSearchCV(RandomForestClassifier(), param_dist, n_iter=20, cv=5, scoring='f1', n_jobs=-1) rand.fit(X_train, y_train)
Say this
"GridSearchCV exhaustively tries every combination of hyperparameters — reliable but exponentially slow as parameters increase. RandomizedSearchCV samples n random combinations — much faster and often finds near-optimal parameters in a fraction of the time. I start with RandomizedSearchCV with a broad search space, then narrow down with GridSearchCV around the best region. Both use cross-validation internally, so n_jobs=-1 parallelises across all CPU cores."

Q19How do you compute a rolling average / moving window in Pandas?
▼
# Rolling mean — 7-day moving average df['sales_7day_avg'] = df['sales'].rolling(window=7).mean() # Rolling with min_periods (handles start of series) df['sales_7day_avg'] = df['sales'].rolling(window=7, min_periods=1).mean() # Expanding window — cumulative mean df['cumulative_avg'] = df['sales'].expanding().mean() # Grouped rolling — rolling per group df['dept_7day'] = df.groupby('department')['sales']\ .transform(lambda x: x.rolling(7).mean())
Say this
"Rolling functions in Pandas apply a function over a sliding window of rows. rolling(7).mean() gives a 7-period moving average — the first 6 values are NaN by default since there aren't enough preceding rows. Setting min_periods=1 starts computing from the first row using however many values are available. For time series analysis rolling averages are essential for smoothing noise and identifying trends."

Q22How do you write efficient Python / Pandas code? Common performance tips.
▼
Vectorise firstAlways prefer vectorised Pandas/NumPy operations over Python loops. 10–100x faster.
Avoid apply loopsdf.apply is a Python loop under the hood. Replace with vectorised operations or numpy where possible.
Use correct dtypesStore categories as category dtype not object. Use int32 not int64 where possible. Reduces memory by 50–90%.
Boolean indexingdf[mask] is faster than df.loc[mask] in most cases for simple filters.
Read in chunkspd.read_csv(..., chunksize=10000) for files larger than memory.
# Bad — Python loop for i, row in df.iterrows(): df.loc[i,'tax'] = row['salary'] * 0.2 # Good — vectorised df['tax'] = df['salary'] * 0.2 # Save memory with category dtype df['city'] = df['city'].astype('category') # can save 80% memory
Say this
"The biggest performance win in Pandas is avoiding loops — iterrows is extremely slow on large DataFrames. Replace any loop with a vectorised operation — it's both faster and more readable. For memory I convert high-cardinality string columns to category dtype which can reduce memory usage by 80–90%. For very large files that don't fit in memory I read in chunks with chunksize and process each chunk separately."
Q23How do you build a full ML pipeline from raw data to prediction?
▼
import pandas as pd import numpy as np from sklearn.model_selection import train_test_split, cross_val_score from sklearn.pipeline import Pipeline from sklearn.compose import ColumnTransformer from sklearn.preprocessing import StandardScaler, OneHotEncoder from sklearn.impute import SimpleImputer from sklearn.ensemble import RandomForestClassifier from sklearn.metrics import classification_report # 1. Load and split FIRST df = pd.read_csv('data.csv') X = df.drop('target', axis=1) y = df['target'] X_train, X_test, y_train, y_test = train_test_split( X, y, test_size=0.2, stratify=y, random_state=42) # 2. Define column groups num_cols = X.select_dtypes('number').columns.tolist() cat_cols = X.select_dtypes('object').columns.tolist() # 3. Build preprocessor num_pipe = Pipeline([ ('imputer', SimpleImputer(strategy='mean')), ('scaler', StandardScaler()) ]) cat_pipe = Pipeline([ ('imputer', SimpleImputer(strategy='most_frequent')), ('encoder', OneHotEncoder(handle_unknown='ignore', drop='first')) ]) preprocessor = ColumnTransformer([ ('num', num_pipe, num_cols), ('cat', cat_pipe, cat_cols) ]) # 4. Full pipeline full_pipe = Pipeline([ ('preprocessor', preprocessor), ('model', RandomForestClassifier(n_estimators=100, random_state=42)) ]) # 5. Cross-validate cv_scores = cross_val_score(full_pipe, X_train, y_train, cv=5, scoring='f1') print(f'CV F1: {cv_scores.mean():.3f} ± {cv_scores.std():.3f}') # 6. Final evaluation on test set full_pipe.fit(X_train, y_train) y_pred = full_pipe.predict(X_test) print(classification_report(y_test, y_pred))
Say this
"This is the production-ready ML workflow. I always split before any preprocessing to avoid leakage. I use ColumnTransformer to apply different pipelines to numerical and categorical columns simultaneously. The full pipeline wraps preprocessing and the model — so cross-validation refits preprocessing on each fold correctly. The test set is only touched once at the very end for the final evaluation number."
