The basics
Q1What is machine learning?
▼

The foundation question. Keep it simple — one clear definition + one real example.

Say this
"Machine learning is a way of teaching computers to learn patterns from data, instead of programming them with explicit rules. For example, instead of writing 'if email contains the word free then spam', you show the model thousands of spam and non-spam emails and it learns the pattern on its own. The more data it sees, the better it gets."
Bonus line
"Traditional programming is rules → data → output. Machine learning is data → output → rules."
Q2What are the three types of machine learning?
▼
Supervised
Labelled data
You give the model data with the correct answers. It learns to predict. e.g. house price prediction, spam detection.
Unsupervised
No labels
No correct answers given. Model finds patterns and groups on its own. e.g. customer segmentation, topic modelling.
Reinforcement
Reward & penalty
Agent takes actions, gets rewards or penalties, learns what to do. e.g. game-playing AI, robotics.
Say this
"Supervised learning trains on labelled data to predict an output — like predicting house prices. Unsupervised learning finds hidden structure in data without labels — like grouping customers by behaviour. Reinforcement learning trains an agent through trial and error using rewards — like teaching a robot to walk."
Q3What is the difference between classification and regression?
▼
Classification
Predicts a category
Output is a class label. e.g. spam/not spam, cat/dog, disease/no disease.
Regression
Predicts a number
Output is a continuous value. e.g. house price, temperature, stock price.
Say this
"Classification predicts which category something belongs to — the output is a label, like 'fraud' or 'not fraud'. Regression predicts a continuous number — like predicting the exact price of a house. The key question is: am I predicting a category or a number?"
Overfitting & underfitting
Q4What is overfitting and underfitting?
▼
Overfitting
Memorised the training data
Model is too complex. Works perfectly on training data but fails on new data. Like a student who memorised answers without understanding.
Underfitting
Too simple to learn
Model is too simple to capture the pattern. Performs badly on both training and new data. Like a student who didn't study at all.
Say this
"Overfitting is when a model learns the training data too well — including the noise — so it fails on new data. Underfitting is when the model is too simple to capture the underlying pattern and performs poorly everywhere. The goal is the sweet spot in the middle — a model that generalises well to unseen data."
How to detect it
Overfitting: training accuracy high, validation accuracy low. Underfitting: both training and validation accuracy are low.
Q5What is the bias-variance tradeoff?
▼
Bias
Error from wrong assumptions
High bias = model is too simple, misses the real pattern. Leads to underfitting.
Variance
Error from sensitivity to data
High variance = model is too complex, reacts to noise. Leads to overfitting.
Total error = Bias² + Variance + Irreducible noise
Say this
"Bias is the error from a model being too simple — it consistently makes wrong assumptions. Variance is the error from a model being too sensitive to the training data — small changes in data cause big changes in predictions. The tradeoff is that reducing bias usually increases variance and vice versa. A simple model like linear regression has high bias, low variance. A complex model like a deep tree has low bias, high variance. The goal is to find the model complexity that minimises total error."
Simple analogy
Bias = consistently aim left of the target. Variance = random scatter all over the target. You want to hit the bullseye — low bias AND low variance.
Q6How do you prevent overfitting?
▼
More dataMost effective fix. More training examples give the model less chance to memorise noise.
RegularisationL1 (Lasso) or L2 (Ridge) — penalises large coefficients to keep the model simpler.
Cross-validationTest the model on held-out data repeatedly to detect overfitting early.
Dropout (NN)Randomly switch off neurons during training so the network can't rely too heavily on any one path.
Simpler modelReduce model complexity — fewer features, shallower tree depth, fewer layers.
Early stoppingStop training when validation loss starts increasing — before the model memorises the training data.
Say this
"The main strategies are: get more data, apply regularisation like L1 or L2 to penalise model complexity, use cross-validation to monitor generalisation, and use early stopping in neural networks. The root cause of overfitting is a model that's too complex for the amount of data available — so either increase data or decrease complexity."
Training & evaluation
Q7What is cross-validation?
▼

Instead of using one fixed train/test split, cross-validation rotates which portion of data is the test set, giving a more reliable estimate of performance.

Say this
"Cross-validation is a technique to evaluate how well a model generalises. In k-fold cross-validation, you split the data into k equal parts. You train on k-1 parts and test on the remaining part, then rotate until every part has been the test set once. You average the k scores. This gives a much more reliable performance estimate than a single train/test split, because every data point gets used for both training and testing."
Most common
5-fold and 10-fold are the standard choices. Use stratified k-fold for classification to ensure each fold has the same class distribution.
Q8What is regularisation? L1 vs L2?
▼

Regularisation adds a penalty to the loss function to stop the model from making coefficients too large — which causes overfitting.

L1 (Lasso): Loss + λ × Σ|weights| → drives some weights to exactly zero
L2 (Ridge): Loss + λ × Σweights² → shrinks all weights, none to zero
L1 — Lasso
Produces sparse models
Sets irrelevant feature weights to exactly 0. Useful for feature selection. Use when you have many features and suspect most are irrelevant.
L2 — Ridge
Shrinks all weights
Keeps all features but makes them small. Works better when all features are somewhat relevant. Most common default choice.
Say this
"Regularisation adds a penalty to the model's loss function to discourage large weights, which reduces overfitting. L1 regularisation — Lasso — shrinks some weights all the way to zero, effectively removing features, so it also does feature selection. L2 — Ridge — shrinks all weights but keeps them all. Use L1 when you suspect many features are irrelevant, L2 as the default when all features might matter."
Q9What evaluation metrics do you use? Accuracy, precision, recall, F1?
▼
Accuracy = (TP + TN) / Total — overall % correct
Precision = TP / (TP + FP) — of predicted positives, how many were right?
Recall = TP / (TP + FN) — of actual positives, how many did we catch?
F1 = 2 × (Precision × Recall) / (Precision + Recall)
Use accuracyWhen classes are balanced. Not useful for imbalanced data.
Use precisionWhen false positives are costly. e.g. spam filter — don't want real emails marked spam.
Use recallWhen false negatives are costly. e.g. cancer detection — don't miss a real case.
Use F1When you need balance between precision and recall. Good for imbalanced datasets.
Say this
"Accuracy is just the percentage correct — but it's misleading on imbalanced data. If 99% of transactions are normal, a model that always predicts normal gets 99% accuracy but catches zero fraud. Precision measures how many of our positive predictions were right. Recall measures how many real positives we caught. F1 is the harmonic mean of the two — useful when you care about both. The choice depends on the cost of false positives vs false negatives in the specific problem."
Core concepts
Q10What is the curse of dimensionality?
▼

As you add more features (dimensions), the data becomes increasingly sparse and models become harder to train.

Say this
"The curse of dimensionality means that as the number of features grows, the amount of data needed to cover the feature space grows exponentially. In high dimensions, all data points become very far apart from each other, which breaks distance-based algorithms like KNN. It also leads to overfitting because the model has too many features relative to the number of training examples. Solutions include feature selection, dimensionality reduction techniques like PCA, and collecting more data."
Simple analogy
In 1D, 10 points cover a line well. In 2D you need 100. In 3D you need 1000. In 100 dimensions you'd need 10¹⁰⁰ points to cover the space — impossible.
Q11What is feature engineering?
▼
Say this
"Feature engineering is the process of using domain knowledge to create, transform, or select input features that make the model perform better. For example, from a raw datetime column you might extract hour of day, day of week, and is_weekend — all of which might be more useful than the raw timestamp. Good feature engineering often matters more than the choice of algorithm. It's one part creativity, one part domain expertise."
EncodingConvert categories to numbers — one-hot encoding, label encoding.
ScalingNormalise or standardise numerical features so they're on the same scale.
InteractionMultiply or combine features — e.g. height × weight = body mass proxy.
BinningConvert continuous values into buckets — e.g. age → young/middle/senior.
Q12What is gradient descent?
▼

The core optimisation algorithm used to train almost all ML models.

Say this
"Gradient descent is the algorithm that minimises a model's loss function by iteratively adjusting the model's weights. Imagine you're blindfolded on a hilly landscape trying to reach the lowest point — you feel which direction goes downhill and take a step that way. The gradient tells you the slope, and the learning rate controls how big each step is. In machine learning, we repeat this process — calculate gradient of loss, update weights in the direction that reduces loss — until the model converges."
Batch GD
Uses all data per step
Stable but very slow on large datasets.
Stochastic (SGD)
One sample per step
Fast but noisy. Mini-batch GD is the practical middle ground.
Common algorithms
Q13Explain decision trees and random forests.
▼
Say this
"A decision tree splits data into branches based on feature values — like a flowchart of yes/no questions — until it reaches a prediction. They're easy to interpret but prone to overfitting. A random forest builds hundreds of decision trees, each trained on a random subset of data and features, then takes a majority vote. The randomness makes each tree different, and averaging their predictions cancels out individual errors. Random forests are robust, handle missing values well, and rarely overfit — they're one of the most reliable off-the-shelf algorithms."
Key point
Random forests reduce variance without increasing bias much — this is the ensemble principle. Many weak models combined make one strong model.
Q14What is the difference between bagging and boosting?
▼
Bagging
Parallel, reduces variance
Train many models independently on random subsets. Combine by averaging or voting. e.g. Random Forest.
Boosting
Sequential, reduces bias
Train models one after another, each fixing the errors of the previous. e.g. XGBoost, AdaBoost, LightGBM.
Say this
"Bagging trains multiple models in parallel on random samples and combines their outputs — it reduces variance and prevents overfitting. Random Forest is the classic example. Boosting trains models sequentially, where each new model focuses on the examples the previous one got wrong — it reduces bias and builds a strong model from weak ones. XGBoost and LightGBM are boosting algorithms and are typically the top performers on tabular data."
Q15What is logistic regression? Is it classification or regression?
▼

Despite the name, logistic regression is a classification algorithm — this trips up many candidates.

Say this
"Despite the name, logistic regression is a classification algorithm, not regression. It predicts the probability that something belongs to a class — like the probability an email is spam. It takes a linear combination of features, passes it through a sigmoid function that squashes the output to between 0 and 1, and then applies a threshold — usually 0.5 — to decide the class. It's simple, fast, interpretable, and works well as a baseline for binary classification problems."
The name trap
Interviewers sometimes ask "what type of problem does logistic regression solve?" to catch people saying "regression." The answer is classification.
Q16How do you handle imbalanced datasets?
▼

Classic real-world problem — fraud detection, disease diagnosis, churn prediction all have far more negatives than positives.

Better metricStop using accuracy. Use precision, recall, F1, or AUC-ROC instead.
OversamplingDuplicate or generate minority class samples. SMOTE creates synthetic samples by interpolating between existing minority examples.
UndersamplingReduce majority class samples to balance the ratio. Risk: losing information.
Class weightsTell the model to penalise mistakes on the minority class more heavily. Most sklearn models have class_weight='balanced'.
Threshold tuningAdjust the classification threshold from 0.5 to catch more positives at the cost of more false alarms.
Say this
"For imbalanced data, first I'd switch from accuracy to F1 score or AUC-ROC. Then I'd try class weights — most models support this natively and it's the simplest fix. If needed, I'd use SMOTE to generate synthetic minority class samples. I'd also tune the classification threshold based on the business need — sometimes catching more true positives is worth accepting more false alarms."
Q17What is the difference between parametric and non-parametric models?
▼
Parametric
Fixed number of parameters
Assumes a specific form for the data. Faster, less data needed. e.g. Linear regression, Logistic regression, Naive Bayes.
Non-parametric
Parameters grow with data
No fixed assumption about data shape. More flexible, needs more data. e.g. KNN, Decision Trees, SVM.
Say this
"Parametric models assume a fixed mathematical form for the data — like linear regression assuming a straight line relationship — and have a fixed number of parameters regardless of data size. They're fast and need less data but can be wrong if the assumption is wrong. Non-parametric models make no such assumptions and can adapt their complexity to the data, but they need more data and are slower. KNN and decision trees are non-parametric."
Q18What is a confusion matrix?
▼

Say this
"A confusion matrix shows the breakdown of correct and incorrect predictions for a classification model. The rows are actual classes, the columns are predicted classes. The diagonal — true positives and true negatives — are correct predictions. Off-diagonal entries are errors. From the confusion matrix you can compute precision, recall, F1, and accuracy. It's much more informative than a single accuracy number because it shows you exactly which types of errors the model is making."
