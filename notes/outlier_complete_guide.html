Outliers — complete guide

What they are, how to find them, and how to handle them.

Foundation

What is an outlier? (deep definition)

▼

You already have the right instinct — an outlier is a value that is very different from the rest of the data. But the full definition goes deeper than just "too big or too small."

An outlier is a data point that deviates so much from the other observations that it raises the question: does this point belong to the same distribution as the rest?

Global outlier
Extreme overall
A value extreme compared to the entire dataset. Most common type. e.g. salary of £2M in a dataset where most earn £35k.
Contextual outlier
Extreme in context
Normal globally but extreme in context. e.g. 30°C temperature is normal in July, but an outlier in January.
Collective outlier
Group is unusual
Individual values look normal but together they form an unusual pattern. e.g. a flat region in a normally fluctuating signal.
Why do outliers exist? The four causes:
Data entry errorSomeone typed 9999 instead of 99. Age = 999. Salary = £0. These are noise — should be fixed or removed.
Measurement errorSensor malfunction, broken scale, corrupted reading. The data is wrong, not the real world.
Sampling errorA CEO accidentally included in a salary survey of junior staff. Wrong population sampled.
Genuine rarityA real event that is just rare — Usain Bolt's speed, a viral tweet, a market crash. These are true outliers that carry real information and should NOT be removed.
Most important point for interviews
Never blindly remove outliers. First ask: why does this outlier exist? If it's an error — fix or remove it. If it's genuine — keep it, or use models that are robust to it. Removing real outliers = losing real information.
Say this in an interview
"An outlier is a data point that deviates significantly from the rest of the distribution. But before deciding what to do with it, I always investigate the cause. Outliers can arise from data entry errors, measurement failures, or sampling issues — in which case they should be corrected or removed. But they can also be genuine extreme events that carry the most interesting signal in the data, like a fraud transaction or a viral post. The treatment depends entirely on the cause."
Detection 1

IQR method (Tukey's fences) — non-parametric

▼

This is the method used by box plots. It makes no assumption about the shape of the distribution — works even with skewed data. You already know IQR = Q3 − Q1.

Lower fence = Q1 − 1.5 × IQR
Upper fence = Q3 + 1.5 × IQR
Extreme outlier: Q1 − 3×IQR or Q3 + 3×IQR (sometimes called "far out")
Live example — salary data (£k). Drag the outlier slider.
Outlier value: £200k
Pros
Works for any distribution. Not affected by the outliers themselves. Simple to calculate by hand. The industry default.
Cons
Can flag too many points in heavily skewed data. The 1.5 multiplier is a convention, not a law — may need tuning.
Say this in an interview
"The IQR method uses Tukey's fences — Q1 minus 1.5 times IQR as the lower bound, and Q3 plus 1.5 times IQR as the upper bound. Anything outside these fences is flagged as an outlier. The key advantage is it's non-parametric — it doesn't assume a normal distribution, so it's reliable even for skewed data like salary or house prices."
Detection 2

Z-score method — for normally distributed data

▼

The Z-score tells you how many standard deviations a point is away from the mean. If a value is more than 3 standard deviations away, it's considered an outlier.

Z = (x − μ) / σ
Outlier threshold: |Z| > 2 (lenient) or |Z| > 3 (strict, most common)
Worked example:
DatasetExam scores: mean = 70, std dev = 8
Score = 95Z = (95 − 70) / 8 = 3.125 → |Z| > 3 → outlier
Score = 55Z = (55 − 70) / 8 = −1.875 → |Z| < 3 → not an outlier
Score = 20Z = (20 − 70) / 8 = −6.25 → extreme outlier — possible data error
Pros
Gives a precise numeric score. Easy to interpret. Works well for normally distributed, symmetric data.
Cons
Uses mean and std dev — both are themselves sensitive to outliers. Can be unreliable when outliers are severe or data is skewed. Assumes normality.
When to choose IQR vs Z-score
Data is normal/symmetric → Z-score works fine. Data is skewed (income, prices, web traffic) → use IQR. Data has extreme outliers already → use IQR (Z-score's mean and std dev are distorted by those same outliers, making them less reliable detectors).
Say this in an interview
"The Z-score method calculates how many standard deviations a point is from the mean. Values with |Z| greater than 3 are typically flagged as outliers. It's intuitive and gives a precise measure, but it assumes the data is roughly normal and it's sensitive to extreme values — the outliers themselves distort the mean and std dev used in the calculation. For skewed data, I prefer the IQR method."
Detection 3

Visual methods — always do these first

▼

Before any calculation, plot your data. Numbers can miss patterns that your eye catches instantly. These are the three essential plots for outlier detection:

Box plot
Best for distributions
Shows Q1, Q3, IQR, fences and outlier dots all at once. Best first look for any numerical column.
Scatter plot
Best for relationships
Reveals outliers in two-dimensional space — a point that is isolated from the cluster of other points.
Histogram
Best for single columns
Shows the full shape of a distribution. Isolated bars far from the main bulk are immediate outlier signals.
Say this in an interview
"I always start with visualisation before running any statistical test. A box plot immediately shows outlier dots beyond the whiskers. A scatter plot reveals bivariate outliers that wouldn't be visible in a single-column analysis. Only after visual inspection do I apply IQR or Z-score to formally quantify and flag them."
Treatment

What to do with outliers — 5 strategies

▼

This is what separates good analysts from great ones. The treatment must match the cause.

Strategy 1
Remove it
Only if confirmed as a data error. Document what you removed and why. Never silently drop rows.
Strategy 2
Cap it (Winsorize)
Replace extreme values with the fence value (e.g. anything above P99 becomes P99). Keeps the row, reduces distortion.
Strategy 3
Transform it
Apply log, sqrt, or Box-Cox transform to compress the scale. Makes extreme values less extreme without removing information.
Strategy 4
Keep it
If the outlier is genuine and important (fraud, viral event, record performance). Use robust models like tree-based methods that aren't sensitive to extreme values.
Strategy 5
Treat separately
Build a separate model or segment for the outlier group. e.g. model whale customers separately from average users.
Log transformation explained simply: If your salary data has values like [30k, 35k, 40k, 500k], taking log gives [10.3, 10.5, 10.6, 13.1]. The gap between the outlier and the rest shrinks dramatically. Very common for right-skewed data like income, prices, and population.
Say this in an interview
"My approach to handling outliers depends on their cause. If it's a data entry or measurement error, I'll correct or remove it — with documentation. If it's a genuine extreme value, I have several options: I can cap it using Winsorization at the 99th percentile, apply a log transform to compress the scale, keep it and use tree-based models that are naturally robust to outliers, or model the outlier group separately. I never blindly delete outliers — every removal is a decision that needs justification."
Impact

How outliers affect ML models

▼

Outliers don't just distort statistics — they can severely damage model performance. Knowing which models are sensitive vs robust shows real depth.

Sensitive to outliers
Handle with care
Linear regression — outliers pull the best-fit line dramatically.

K-means clustering — outliers distort cluster centroids.

KNN — distance-based, so extreme values dominate nearest-neighbour calculations.

PCA — outliers inflate variance in principal components.
Robust to outliers
Naturally resilient
Decision trees / Random Forest — split on thresholds, not distances.

Gradient boosting (XGBoost) — tree-based, handles skew well.

Median-based methods — median is robust to extremes by definition.

SVM with RBF kernel — uses support vectors, not all points.
Say this in an interview
"Outliers have very different impacts depending on the algorithm. Linear regression and K-means are highly sensitive because they're based on means and distances — a single extreme value can shift the regression line or a centroid significantly. Tree-based models like Random Forest and XGBoost are naturally robust because they split on value ranges rather than computing distances. So my outlier treatment strategy changes based on which model I'm using downstream."
