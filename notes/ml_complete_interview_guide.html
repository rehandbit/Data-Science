Core ML concepts
Q1What is machine learning and how is it different from traditional programming?
▼
Traditional programming
Rules → Output
You write explicit rules. Input + rules = output. e.g. IF email contains "free money" THEN spam.
Machine learning
Data → Rules
You provide data + outputs. Algorithm learns the rules itself. e.g. show 10,000 spam emails, it learns the pattern.
Say this
"Machine learning is a way of getting computers to learn patterns from data rather than following explicit rules. In traditional programming you write the logic — input plus rules gives output. In ML you flip it — you give input and output and the algorithm figures out the rules. The more data it sees, the better it gets. It's especially useful when the rules are too complex to write manually, like recognising faces or detecting fraud."
Bonus line
"Traditional programming: rules + data → output. ML: data + output → rules."
Q2What are the three types of ML? Supervised, unsupervised, reinforcement.
▼
Supervised
Labelled data
Every training example has an answer (label). Model learns to predict labels. e.g. house price, spam detection, image classification.
Unsupervised
No labels
No correct answers. Model finds hidden structure on its own. e.g. customer segmentation, anomaly detection, topic modelling.
Reinforcement
Reward & penalty
Agent learns by trial and error — actions get rewards or penalties. e.g. game AI, robotics, self-driving.
Say this
"Supervised learning trains on labelled examples — every row has a correct answer — and learns to predict that answer on new data. Unsupervised learning finds hidden patterns without any labels, like grouping customers by behaviour. Reinforcement learning trains an agent through trial and error — it takes actions, receives rewards or penalties, and gradually learns the best strategy. In data science roles, supervised learning is most common day-to-day."
Q3What is the difference between regression and classification?
▼
Regression
Predicts a number
Output is a continuous value. e.g. house price, temperature, stock price, customer lifetime value. Use MAE, RMSE, R² to evaluate.
Classification
Predicts a category
Output is a class label. Binary (yes/no) or multiclass (cat/dog/bird). e.g. spam, fraud, disease. Use accuracy, F1, AUC-ROC.
Binary classificationTwo possible classes. e.g. fraud / not fraud, spam / not spam.
MulticlassMore than two classes. e.g. classify image as cat, dog, or bird.
Multi-labelEach sample can belong to multiple classes at once. e.g. a movie can be both action AND comedy.
Say this
"Regression predicts a continuous number — the exact value matters. Classification predicts which category something belongs to. The question to ask is: am I predicting a number or a label? Predicting salary is regression. Predicting whether someone will churn is classification. They use different loss functions, different evaluation metrics, and different output layers in neural networks."
Logistic regression trap
Despite the name, logistic regression is a CLASSIFICATION algorithm, not regression. It predicts the probability of a class. This catches many candidates off guard.
Q4What is overfitting and underfitting? How do you detect and fix them?
▼
Overfitting
Memorised the noise
Train accuracy high, validation accuracy low. Model too complex — memorised training data including noise.
Underfitting
Too simple to learn
Both train and validation accuracy low. Model too simple to capture the real pattern in the data.
Good fit
Generalises well
Train and validation accuracy both high and close to each other. Learns the signal without memorising noise.
Fix overfittingGet more data. Regularisation (L1/L2). Dropout (neural nets). Cross-validation. Reduce model complexity. Early stopping.
Fix underfittingUse more complex model. Add more features. Train longer. Reduce regularisation strength. Better feature engineering.
Say this
"Overfitting is when the model memorises training data — including the noise — so it fails on new data. I detect it by comparing training vs validation accuracy — a big gap means overfitting. I fix it by adding regularisation, getting more training data, using dropout, or reducing model complexity. Underfitting means the model is too simple — both training and validation accuracy are low. The fix is a more complex model or better features."
Q5What is the bias-variance tradeoff?
▼
Bias
Error from wrong assumptions
High bias = model too simple, systematically misses the pattern. Leads to underfitting. e.g. linear model on non-linear data.
Variance
Error from sensitivity
High variance = model too sensitive to training data, changes a lot with small data changes. Leads to overfitting.
Total error = Bias² + Variance + Irreducible noise
High bias modelLinear regression, Naive Bayes. Simple, stable but may underfit.
High variance modelDeep decision tree, KNN with k=1. Flexible but overfits easily.
BalancedRandom Forest, XGBoost, tuned neural net. Best of both worlds.
Say this
"Bias is systematic error from the model being too simple — it consistently misses the real pattern. Variance is how much the model's predictions change when trained on different data — high variance means it's overfitting. Reducing bias usually increases variance and vice versa — that's the tradeoff. A simple model like linear regression has high bias but low variance. A deep unpruned tree has low bias but high variance. The goal is finding the sweet spot that minimises total error."
Analogy
Bias = always aim left of the target. Variance = random scatter all over the target. You want low bias AND low variance — hitting the bullseye consistently.
Q6What is the difference between a parameter and a hyperparameter?
▼
Parameter
Learned from data
Internal values the model learns during training. e.g. weights in a neural network, coefficients in linear regression. You don't set these manually.
Hyperparameter
Set before training
Configuration values YOU set before training starts. e.g. learning rate, number of trees, max depth, regularisation strength, k in KNN.
Say this
"Parameters are the internal values a model learns from data during training — like the weights in a neural network or the slope in linear regression. Hyperparameters are settings you configure before training begins — like the learning rate, number of trees in a forest, or depth of a tree. You tune hyperparameters through techniques like grid search or random search using a validation set."
Q7What is cross-validation and why do we need it?
▼

Evaluating model performance on data it has never seen during training.

K-fold CVSplit data into k equal folds. Train on k-1, test on 1, rotate k times. Average the k scores. Most common — use k=5 or k=10.
Stratified k-foldSame as k-fold but each fold preserves class distribution. Essential for imbalanced classification.
Leave-one-outEach single sample is the test set once. Exhaustive, very slow. Only for tiny datasets.
Time series splitAlways train on past, test on future. Never shuffle. Prevents data leakage from future into past.
Say this
"Cross-validation gives a reliable estimate of how well a model generalises to unseen data. In k-fold, I split data into k parts and rotate which part is the test set — every sample gets tested exactly once. A single train-test split can be lucky or unlucky depending on which data ended up in each set. Cross-validation averages across k splits, giving a much more stable estimate. I always use stratified k-fold for classification to maintain class distribution in each fold."
Q8What is feature engineering and feature selection? Why do they matter?
▼
Feature engineering
Creating better features
Using domain knowledge to transform or create new input features. e.g. extracting day_of_week from a timestamp, creating interaction terms, log-transforming skewed features.
Feature selection
Choosing the best features
Removing irrelevant or redundant features. Reduces overfitting, speeds up training, improves interpretability. e.g. correlation filter, Lasso, feature importance.
Filter methodsSelect features based on statistical scores (correlation, chi-square) before training. Fast but ignores feature interactions.
Wrapper methodsTry different subsets and evaluate model performance. Recursive Feature Elimination (RFE). Slow but accurate.
Embedded methodsSelection happens during training. Lasso sets irrelevant weights to zero. Tree feature importance. Most efficient.
Say this
"Feature engineering is creating or transforming input features using domain knowledge — it often matters more than the choice of algorithm. For example, extracting hour-of-day and is_weekend from a timestamp can be far more predictive than the raw timestamp. Feature selection removes irrelevant or redundant features to reduce overfitting and improve model speed. My preferred approach is embedded selection using tree feature importance or Lasso regularisation — selection happens during training without an extra step."
Model evaluation metrics
Q9What is a confusion matrix and what metrics come from it?
▼
Predicted positive
Predicted negative
Actual positive
TP
True positive
Correct alarm
FN
False negative
Missed it
Actual negative
FP
False positive
False alarm
TN
True negative
Correct rejection
Accuracy = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP) — of predicted positives, how many were right?
Recall = TP / (TP + FN) — of actual positives, how many did we catch?
F1 = 2 × (Precision × Recall) / (Precision + Recall)
Say this
"A confusion matrix breaks predictions into four cells — true positives, true negatives, false positives, and false negatives. From this we derive accuracy, precision, recall, and F1. Accuracy is misleading on imbalanced data — a model that always predicts 'not fraud' on 99% non-fraud data gets 99% accuracy but catches zero fraud. Precision measures how reliable our positive predictions are. Recall measures how many real positives we found. F1 balances both."
Q10When do you use precision vs recall? Which is more important?
▼
Precision — minimise false positives
Use when FP is costly
Spam filter — a false positive flags a real email as spam. Annoying, erodes user trust. Better to miss some spam than delete real emails.
Recall — minimise false negatives
Use when FN is costly
Cancer screening — a false negative misses a real cancer case. Missing a diagnosis can be fatal. Better to over-alert than miss real cases.
Use F1When you need balance between precision and recall — imbalanced classification, fraud detection.
Use precisionSpam filters, recommendation systems, ad targeting. False positives are annoying or wasteful.
Use recallMedical diagnosis, safety systems, fraud detection (catch all fraud). Missing a case is dangerous.
Say this
"Which matters more depends on the cost of each type of error. Precision is critical when false positives are costly — like a spam filter where wrongly blocking a real email damages trust. Recall is critical when false negatives are costly — like cancer screening where missing a real case could be fatal. When both matter and the dataset is imbalanced, F1 score is the go-to metric as it's the harmonic mean of both."
Don't say "accuracy is the best metric"
This is the most common wrong answer. Accuracy fails on imbalanced datasets. Always discuss the business cost of false positives vs false negatives first.
Q11What is AUC-ROC? How do you interpret it?
▼

ROC = Receiver Operating Characteristic. AUC = Area Under the Curve. Measures model's ability to discriminate between classes across all thresholds.

X-axis (FPR)False positive rate = FP / (FP + TN). How many negatives are wrongly classified as positive.
Y-axis (TPR)True positive rate = Recall = TP / (TP + FN). How many positives are correctly found.
AUC = 1.0Perfect model. Classifies everything correctly.
AUC = 0.5Random guessing. Diagonal line. Model has no discrimination power.
AUC = 0.7–0.8Acceptable. AUC > 0.8 = good. AUC > 0.9 = excellent.
Say this
"The ROC curve plots true positive rate against false positive rate at every possible classification threshold. AUC — area under this curve — summarises performance in one number. An AUC of 0.85 means if you randomly pick one positive and one negative sample, the model ranks the positive higher 85% of the time. AUC is great for comparing models on imbalanced data because it's threshold-independent — you evaluate performance across all possible thresholds at once."
AUC vs F1
Use AUC when comparing models or when the threshold hasn't been decided yet. Use F1 when you have a specific threshold and care about the specific precision-recall balance at that point.
Q12What are regression metrics — MAE, MSE, RMSE, R²?
▼
MAE = (1/n) × Σ|actual − predicted| — mean absolute error
MSE = (1/n) × Σ(actual − predicted)² — mean squared error
RMSE = √MSE — root mean squared error
R² = 1 − (SS_res / SS_tot) — coefficient of determination
MAEAverage absolute error. Robust to outliers. Easy to interpret — same units as the target. e.g. average prediction is off by £3,500.
MSESquares errors — penalises large errors heavily. Not in original units. Sensitive to outliers. Used in loss functions.
RMSESquare root of MSE — back to original units. Still penalises large errors. Most commonly reported metric.
R²Proportion of variance explained. R²=1 is perfect. R²=0 means model is as good as predicting the mean. Can be negative (worse than mean).
Say this
"For regression I use MAE when I want an easily interpretable average error in the original units — it treats all errors equally. RMSE is my default when large errors are especially bad — the squaring penalises them more, and the final units are the same as the target. R-squared tells me what proportion of variance my model explains — 0.85 means the model explains 85% of variance in the target. R-squared is useful for relative comparison but doesn't tell you the absolute magnitude of errors."
R² trap
High R² doesn't always mean a good model — it can be inflated by adding irrelevant features. Use Adjusted R² when comparing models with different numbers of features — it penalises unnecessary features.
Q13How do you handle imbalanced datasets?
▼

When one class dominates — like 99% legitimate transactions and 1% fraud.

Better metricFirst — stop using accuracy. Use F1, precision-recall curve, AUC-ROC, or Matthews Correlation Coefficient.
Class weightsTell the model to penalise mistakes on the minority class more. class_weight='balanced' in sklearn. Simplest fix.
OversamplingDuplicate or synthetically generate minority class rows. SMOTE creates synthetic samples by interpolating between existing minority examples.
UndersamplingReduce majority class. Fast but risks losing information. Use when dataset is very large.
Threshold tuningAdjust classification threshold from 0.5 to a lower value to flag more positives — trades precision for recall.
Say this
"First I switch from accuracy to F1 or AUC-ROC — accuracy is meaningless on imbalanced data. Then my first practical fix is class weights — most sklearn models have class_weight='balanced' which is free and effective. If that's not enough I use SMOTE to generate synthetic minority class examples. I also tune the decision threshold — if catching fraud is critical I lower the threshold to 0.3 so more cases get flagged, accepting some extra false alarms."
Q14What is the difference between validation set and test set?
▼
Training set
Learn from
Model sees this data during training. Learns parameters from it. Typically 60–80% of data.
Validation set
Tune on
Used during development to tune hyperparameters and select the best model. Model indirectly "sees" this. Typically 10–20%.
Test set
Final report card
Touched only ONCE at the very end. Gives honest estimate of real-world performance. Never used for any decisions. Typically 10–20%.
Say this
"Training data is what the model learns from. The validation set is used during development — you tune hyperparameters and compare models using validation performance, which means the model indirectly learns from it too. The test set is sacred — it's touched once at the very end to get an honest estimate of real-world performance. If you use the test set to make any decisions, it becomes another validation set and your final performance estimate will be optimistic."
Data leakage warning
Never fit scalers, encoders, or imputers on the full dataset before splitting. Fit only on training data, then transform validation and test. Otherwise test set statistics contaminate training.
Algorithm intuition
Q15Explain linear regression — how does it work?
▼
y = w₁x₁ + w₂x₂ + ... + wₙxₙ + b
Loss = MSE = (1/n) Σ(actual − predicted)² → minimised by gradient descent
IntuitionFits the best straight line through data that minimises the sum of squared distances from each point to the line.
CoefficientsEach weight shows how much the target changes for a 1-unit increase in that feature, holding all others constant.
AssumptionsLinear relationship. Residuals normally distributed. Homoscedasticity (constant variance). No multicollinearity. Independent observations.
Sensitive toOutliers (they pull the line). Multicollinearity (unstable coefficients). Feature scale (use standardisation).
Say this
"Linear regression finds the best-fit line through data by minimising the mean squared error — the sum of squared vertical distances from each point to the line. It learns a weight for each feature — a coefficient of 3.5 on 'bedrooms' means each extra bedroom adds £3,500 to the predicted price, holding everything else equal. It's fast and interpretable but assumes a linear relationship and is sensitive to outliers."
Q16Explain logistic regression — how does it work?
▼
P(y=1) = sigmoid(w·x + b) = 1 / (1 + e^(-z))
Loss = Binary cross-entropy = -[y·log(p) + (1−y)·log(1−p)]
IntuitionTakes a linear combination of features, passes through sigmoid function to squash to 0–1. Outputs a probability. Threshold (usually 0.5) converts to class label.
SigmoidS-shaped curve. Maps any number to 0–1. Values near 0 = class 0, near 1 = class 1, near 0.5 = uncertain.
OutputA probability — not a hard label. You choose the threshold. Lowering threshold = higher recall, lower precision.
Say this
"Logistic regression takes a linear combination of features — just like linear regression — but passes the result through a sigmoid function that squashes output to between 0 and 1. This gives a probability of belonging to the positive class. A threshold — typically 0.5 — converts that probability to a class label. It's a classification algorithm despite the name, it's interpretable, fast to train, and is an excellent baseline before trying complex models."
Q17Explain decision trees — how do they work?
▼
IntuitionFlowchart of yes/no questions. Each node splits data based on the feature+threshold that best separates classes. Repeats until leaves are pure.
Split criterionGini impurity or entropy (classification). MSE reduction (regression). Picks the split that creates the purest child nodes.
Gini impurityMeasures how often a randomly picked element would be wrongly classified. 0 = pure node (all one class).
ProsHighly interpretable. No feature scaling needed. Handles mixed data types. Captures non-linear relationships.
ConsProne to overfitting — a fully grown tree memorises training data. Unstable — small data changes cause very different trees.
Say this
"A decision tree works like a series of yes/no questions — at each node it picks the feature and threshold that best splits the data into purer groups, measured by Gini impurity or entropy. It keeps splitting until it reaches leaves that are pure or a stopping condition is met. Decision trees are very easy to interpret — you can visualise the exact rules — but they overfit easily. That's why in practice we use ensembles like Random Forest or XGBoost which combine many trees."
Q18Explain Random Forest — what makes it better than a single tree?
▼
IdeaBuild hundreds of different decision trees. Each tree votes on the answer. Final prediction = majority vote (classification) or average (regression).
BaggingEach tree trains on a random sample of rows (with replacement). Different data = different trees.
Feature randomnessEach split considers only a random subset of features (usually √n features). Forces trees to be different from each other.
Why it worksIndividual trees overfit, but in different ways. Their errors cancel out when averaged. Reduces variance without increasing bias much.
Feature importanceMeasures how much each feature reduces impurity across all trees. Free by-product — great for feature selection.
Say this
"Random Forest builds hundreds of decision trees, each trained on a different random sample of rows and each split choosing from a random subset of features. This double randomness ensures the trees are uncorrelated — they make different errors. When you average their predictions, the errors cancel out. A single decision tree overfits badly but Random Forest's averaging reduces variance significantly without much bias increase. It's also robust to outliers, handles missing values, and gives feature importance for free."
Q19What is gradient boosting and how does XGBoost work?
▼
Core ideaBuild trees SEQUENTIALLY. Each new tree specifically fixes the errors of all previous trees. Ensemble of weak learners becomes a strong model.
ResidualsEach tree trains on the residuals (errors) of the combined previous model — not the original target.
Learning rateEach tree's contribution is scaled by a learning rate. Small learning rate + more trees = better generalisation but slower.
XGBoost extrasRegularisation (L1/L2) built in. Handles missing values natively. Parallel processing. Column and row subsampling. Much faster than vanilla gradient boost.
Bagging (Random Forest)
Parallel trees
All trees built independently. Reduces variance. Less prone to overfitting.
Boosting (XGBoost)
Sequential trees
Each tree fixes previous errors. Reduces bias. Can overfit — needs careful tuning of trees and learning rate.
Say this
"Gradient boosting builds trees sequentially — each new tree trains on the errors of all previous trees combined. Start with a simple prediction, compute residuals, build a tree to predict residuals, update the model, repeat. XGBoost improves on this with built-in L1/L2 regularisation, native handling of missing values, and parallel computation. It's the go-to algorithm for tabular data — it consistently wins Kaggle competitions because it reduces both bias and variance when tuned correctly."
Q20Explain K-Nearest Neighbours (KNN) — intuition and limitations.
▼
IntuitionTo classify a new point, find the k closest training points (neighbours). For classification — majority vote. For regression — average of k neighbours.
k = 1Very sensitive — memorises training data. High variance. Overfits.
k = largeToo smooth — boundary becomes blurry. High bias. Underfits.
Distance metricEuclidean distance is default. Features must be scaled — KNN is very sensitive to feature scale. Always standardise first.
LimitationsSlow at prediction — compares to every training point. Fails in high dimensions (curse of dimensionality). No interpretability.
Say this
"KNN is a lazy learner — it stores all training data and at prediction time finds the k closest neighbours and takes a majority vote. The key tuning decision is k — small k is noisy and overfits, large k is too smooth and underfits. You must standardise features before KNN because it's distance-based — a feature in thousands of pounds would dominate one measured in single digits. KNN is slow at prediction on large datasets and struggles in high dimensions where distances become meaningless."
Q21Explain Support Vector Machines (SVM) — intuition.
▼
IntuitionFinds the hyperplane that maximises the margin between two classes. The points closest to the boundary are support vectors — the rest don't matter.
MarginThe gap between the decision boundary and the nearest points of each class. Maximising margin improves generalisation.
Kernel trickMaps data to higher dimensions to find a separating hyperplane that doesn't exist in the original space. RBF kernel is the most popular — handles non-linear boundaries.
C parameterControls the trade-off between maximising margin and minimising misclassifications. High C = hard margin, may overfit. Low C = soft margin, more regularised.
Say this
"SVM finds the decision boundary that maximises the margin between classes — the widest street between two neighbourhoods. Only the data points nearest to the boundary — the support vectors — define it, which makes SVM robust to outliers far from the boundary. The kernel trick transforms data into higher dimensions to separate non-linearly separable classes. SVM works well with high-dimensional data and small datasets but is slow to train on large data and sensitive to feature scaling."
Q22Explain K-Means clustering — how it works and its limitations.
▼
Algorithm1. Randomly initialise k centroids. 2. Assign each point to nearest centroid. 3. Recalculate centroid as mean of assigned points. 4. Repeat until centroids stop moving.
Choose kElbow method — plot inertia vs k, pick where the curve bends. Silhouette score — measures how similar a point is to its own cluster vs other clusters.
LimitationsMust specify k in advance. Sensitive to outliers — they pull centroids. Assumes spherical clusters of equal size. Different initial centroids give different results (use k-means++).
Say this
"K-means randomly places k centroids, assigns each point to the nearest one, then moves each centroid to the mean of its assigned points — and repeats until stable. It's simple and fast but has key limitations: you must choose k in advance, it's sensitive to outliers since centroids are means, and it assumes clusters are spherical and roughly equal in size. To choose k I use the elbow method — plotting inertia against k and looking for where improvement slows down."
Q23Explain Naive Bayes — why is it "naive"?
▼
P(class | features) ∝ P(class) × P(f1|class) × P(f2|class) × ... × P(fn|class)
Naive assumptionAssumes all features are completely independent of each other given the class. In reality features are usually correlated — hence "naive."
Despite naivetyWorks surprisingly well for text classification (spam, sentiment) where the independence assumption is approximately true for word frequencies.
ProsVery fast. Works well with small data. Handles high dimensions well. Great for text (bag of words).
ConsIndependence assumption is almost always violated. Bad probability estimates. Struggles if features are highly correlated.
Say this
"Naive Bayes applies Bayes' theorem with the naive assumption that all features are independent of each other given the class. It's naive because real-world features almost never are truly independent — a word appearing in an email is correlated with what other words appear. Despite this unrealistic assumption it works surprisingly well for text classification because word frequencies are approximately independent, and it's extremely fast to train and predict."
Q24What is PCA and when do you use it?
▼
IntuitionFinds the directions (principal components) of maximum variance in the data. Projects data onto fewer dimensions while keeping most information.
How it worksComputes eigenvectors of the covariance matrix. PC1 captures most variance, PC2 second most (perpendicular to PC1), and so on.
Use forDimensionality reduction. Visualising high-dimensional data in 2D/3D. Removing multicollinearity. Speeding up training.
DownsideComponents are linear combinations of original features — interpretability is lost. Must standardise first — PCA is scale-sensitive.
Say this
"PCA finds the directions of maximum variance in high-dimensional data and projects it onto fewer dimensions — called principal components — while retaining as much variance as possible. It's used for dimensionality reduction when features are many and correlated, for visualising clusters in 2D, and for removing multicollinearity before linear models. A key rule: always standardise features before PCA, because it's sensitive to scale — a feature measured in thousands would dominate one measured in single digits."
Q25What is regularisation? L1 vs L2 — intuition and difference.
▼
L1 (Lasso): Loss + λ Σ|w| → sets some weights exactly to zero (sparse model)
L2 (Ridge): Loss + λ Σw² → shrinks all weights toward zero, none exactly zero
Elastic Net: Loss + λ₁Σ|w| + λ₂Σw² → combines both
L1 — LassoDiamond constraint shape. Corners hit the axes — drives some weights to exactly zero. Performs feature selection automatically. Use when many features are irrelevant.
L2 — RidgeCircular constraint shape. Distributes weight reduction evenly — no weights go to zero. Better when all features matter. Default choice for most linear models.
λ (lambda)Regularisation strength. Higher λ = more penalty = simpler model. Tuned via cross-validation.
Say this
"Regularisation adds a penalty to the loss function for large weights, which prevents overfitting by keeping the model simpler. L1 — Lasso — penalises the absolute value of weights and drives some all the way to zero, effectively doing feature selection. L2 — Ridge — penalises squared weights and shrinks all weights evenly but never to zero. I use L1 when I suspect many features are irrelevant and want automatic selection. I use L2 as the default when all features are potentially useful."
Q26What is gradient descent? Batch, stochastic, mini-batch?
▼
IntuitionIteratively adjusts model weights in the direction that reduces the loss. Like walking downhill blindfolded — follow the slope until you reach the bottom.
weight = weight − learning_rate × gradient_of_loss
Batch GDComputes gradient on the FULL dataset per step. Stable but very slow on large data. Memory-intensive.
Stochastic (SGD)Computes gradient on ONE random sample per step. Very fast, noisy. Can escape local minima. Used in large-scale ML.
Mini-batch GDComputes gradient on a small batch (32–256 samples). Best of both — fast and stable. Standard in deep learning.
Learning rateToo high = overshoots minimum, diverges. Too low = very slow convergence. Use learning rate schedulers or Adam optimiser.
Say this
"Gradient descent minimises the loss function by repeatedly moving weights in the direction of steepest descent — the negative gradient. Batch gradient descent is stable but slow because it uses the full dataset per update. Stochastic uses one sample — fast and noisy. Mini-batch is the practical standard — uses 32 to 256 samples per update, balancing speed and stability. The learning rate controls step size — too large and you overshoot, too small and training takes forever."
Q27What is the curse of dimensionality?
▼

As the number of features grows, the data becomes increasingly sparse and models become harder to train.

The problemIn high dimensions, all data points become approximately equidistant from each other. Distance-based algorithms like KNN break down — neighbours are no longer meaningful.
SparsityTo cover a 10-dimensional space as densely as 1D, you need 10^10 times more data. You almost never have enough data in high dimensions.
SolutionsFeature selection — remove irrelevant features. PCA — project to fewer dimensions. Regularisation — penalise complexity. Collect more data.
Say this
"The curse of dimensionality means that as you add more features, the data becomes exponentially sparser — points are far apart from each other in every direction. This breaks distance-based algorithms like KNN because all distances converge to similar values, making nearest neighbours meaningless. It also leads to overfitting because a complex model has too many parameters relative to available data points. The cure is dimensionality reduction — PCA, feature selection, or regularisation."
Analogy
10 points cover a line well. In 2D you need 100. In 3D you need 1,000. In 100 dimensions you'd need 10¹⁰⁰ — impossible to collect.
Q28How do you choose the right algorithm for a problem?
▼
Problem typeClassification → logistic regression, trees, SVM, neural net. Regression → linear regression, trees, SVR. Clustering → K-means, DBSCAN. Dimensionality → PCA.
Dataset sizeSmall → simpler models (logistic, SVM, Naive Bayes). Large → gradient boosting, neural networks.
InterpretabilityNeed to explain? → linear regression, logistic regression, decision tree. Don't need to explain? → XGBoost, neural net.
Speed neededFast training → Naive Bayes, linear models. Accuracy priority → XGBoost, neural nets. Fast prediction → linear models, decision tree.
Data typeTabular → XGBoost, Random Forest. Images → CNN. Text → transformers, Naive Bayes. Time series → LSTM, ARIMA.
Say this
"I always start simple — a logistic regression or decision tree as a baseline. If performance is insufficient, I move to Random Forest or XGBoost for tabular data. My thought process is: what type of problem is it, how much data do I have, do I need interpretability, and how much compute is available? For tabular data XGBoost is almost always the best starting point after the baseline. For images I go straight to CNNs, for text to transformers."
Q29What is data leakage and why is it dangerous?
▼

Data leakage is when information from outside the training data leaks into the model — causing artificially high performance that disappears in production.

Target leakageFeature that is itself derived from the target. e.g. using "claim_amount" to predict whether an insurance claim was fraudulent — claim_amount is 0 for non-fraud.
Train-test leakageFitting preprocessing (scaler, imputer, encoder) on the full dataset before splitting. Test set statistics contaminate training.
Time leakageUsing future information to predict the past. e.g. using tomorrow's data to predict today's stock price.
How to detectSuspiciously high accuracy. Feature importance dominated by one unexpected feature. Performance drops sharply in production.
Say this
"Data leakage happens when information that wouldn't be available at prediction time is used during training. It causes the model to look great on paper but fail completely in production. Target leakage is the most dangerous — a feature that's derived from or directly related to the target. Train-test leakage happens when you fit a scaler or encoder on the full dataset — always fit only on training data, then apply to test. Leakage is often spotted when validation accuracy seems too good to be true."
Q30What is ensemble learning? Bagging vs boosting vs stacking.
▼

Combining multiple models to produce a better prediction than any single model alone.

BaggingTrain models in parallel on random subsets (bootstrap samples). Average predictions. Reduces variance. e.g. Random Forest.
BoostingTrain models sequentially, each fixing errors of the previous. Reduces bias. Can overfit. e.g. XGBoost, LightGBM, AdaBoost.
StackingTrain multiple diverse base models. Use their predictions as features for a meta-model (blender). Most powerful — used heavily in competitions.
VotingSimple ensemble — take majority vote (classification) or average (regression) of multiple different model predictions. Easy, often surprisingly effective.
Say this
"Ensemble learning combines multiple models to outperform any individual model. Bagging trains models in parallel on different data samples and averages — Random Forest is the classic example. Boosting builds models sequentially, each one fixing previous errors — XGBoost is the state of the art here. Stacking trains base models and feeds their predictions into a meta-model — it's the most powerful technique and is common in Kaggle competition winners. The intuition behind all ensembles is that diverse models make different errors, and combining them averages out the mistakes."
